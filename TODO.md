## Defects

- [ ] **An output-limit continuation starts a new Round.** With `MaxTruncatedContinuations` above 0 (it is 0 by default), a reply cut off at the output limit is followed by `UserMessage(TruncatedContinuationText)` (`loop.go`, `limits.go`). The gateway's `roundStart` (`gateway/provider.go`) takes any user Message as the start of a Round, so Claude and OpenAI are no longer sent the cut reply's reasoning, which the model needs to go on. Read from the code, not run. Fixed by FEATURES.md → G-F29, where the continuation becomes a `continue` notice.
- [ ] **The file store checks a writer's epoch a few milliseconds before it writes.** `FileStore.Append` (`session/file.go`) compares the writer's epoch with the Record's, then writes a temporary file, syncs it and links it into the Record's directory, without a lock across the three. A Record that another process, or another goroutine, deletes and creates again under the same ID in that window, at the same length, takes the old writer's batch, and its Summary names the old epoch. `MemoryStore` checks and writes under one lock. Read from the code, not run. Fix: give each Record created under an ID a directory of its own, such as one named by its epoch, so an old writer's link finds no directory. It changes the file store's layout, so stores written before need a migration.
- [ ] **A Segment's tool call lines must escape the arguments they quote.** A tool call's arguments reach a model in a structured field on all three wire APIs (`gateway/anthropic.go`, `gateway/gateway.go`, `gateway/responses.go`), so `ForModel` rightly leaves them as they are. A Segment's `<tool_calls>` lines quote them as text, so an argument holding `</tool_calls>` could end the block early. The code that renders the lines must pass each argument through `EscapeTags` ([FEATURES.md → G-F06](FEATURES.md#g-f06--compaction-)). A Part marked `MetaTag` is trusted, so a ToolSet bridge (MCP, G-F12) must drop that key when it copies foreign metadata into a Tool Result.
- [ ] **`ForModel` does not escape a Tool Result's JSON Parts.** It escapes Parts of kind `text` only (`context.go`), and the Anthropic and Chat Completions encoders send a `json` Part's text to the model as text (`gateway/anthropic.go`, `gateway/gateway.go`). A Tool written as a Go function is safe, because `json.Marshal` writes `<` as `<`; a Tool Result built by hand with a `json` Part is not. Fix: escape `json` Parts too, writing `<` so the JSON keeps its value. Read from the code, not run.
- [ ] **The gateway can miss a refusal as too long, and can mistake another for one.** `readErrorBody` keeps only `error.message` (`gateway/gateway.go`), so an error that names the overflow only in `error.code` or `error.type` is not seen. The six phrases in `gateway/overflow.go` are unchecked against live providers, and "input and `max_tokens` too large" may match one, which compaction cannot fix. Fix: check the wording against each provider, and read `code` and `type` too. Read from the code, not run.

## Decisions

- [ ] **A draining instance refuses a Run with 409, not with a 503 marked "not run".** A Run the draining instance refuses at admission gets `ErrDraining` (`service/service.go`), an `ErrInvalidState`: 409 over HTTP and `FailedPrecondition` over gRPC (FEATURES.md → G-F27 and G-F14). A Run refused past the activation limit gets 503 with `Gotato-Not-Run: true`, so a load balancer may send it to another instance. A draining refusal did not run either, and another instance can serve it, but 409 says the request conflicts with the Session's state. Options: keep 409; or answer 503 with `Gotato-Not-Run: true` over HTTP and `Unavailable` over gRPC, a contract change with a CHANGELOG note. Recommendation: 503 marked "not run", the same as the activation limit, because the request is safe to send elsewhere.
- [ ] **Whether a queued notice outlives its writer.** A notice waits in the queue that holds a Steer, and one still waiting when a Run settles waits for the next Run (FEATURES.md → G-F29). Its `notice_queued` Event is stored in the Record (G-F13), and `Notice` answers with that Event's number. A Steer the writer accepted but has not committed is lost if the writer dies, and the caller sends it again (G-F26). The design does not say whether an instance that loads the Session after its writer died rebuilds the queue from stored `notice_queued` Events that have no `notice_committed`, or drops them. Options: rebuild them on load; or drop them, as with a Steer, and the service sends them again. Recommendation: rebuild them on load, because the service was answered with a stored number and takes the notice as accepted. To settle when Phase 7 builds G-F29.
- [ ] **A Run whose last writes fail still says `completed`.** When the writes that end a Run fail (`writer.Release` in `service/service.go`), the Runner returns the Run's result with its own status, such as `completed`, and adds `ErrNotPersisted` to the error. The caller has already streamed the reply, but the Record does not hold it, so the next Run starts without it. [DESIGNS.md → The store is the only truth](DESIGNS.md#1-the-store-is-the-only-truth) says a step counts only once it is in the store. Seen in `TestFailureLeavesTheSessionUsable` (`service/workload/failure_test.go`), which fails each of a Run's ten writes in turn. Options: keep the status and the added error, as today; or settle such a Run with a status of its own, such as `not_saved`, so a caller that reads only the status cannot take it for a success, a contract change with a CHANGELOG note. Recommendation: a status of its own, because the status is what most callers read.
- [ ] **How large a user Message or a final reply may be inside a Segment.** A Segment keeps both word for word ([FEATURES.md → G-F06](FEATURES.md#g-f06--compaction-)), and nothing bounds them: a user who pastes a 50K-token log, or an Agent whose final reply is a long report, makes a Segment as large as the stretch it closes. Options: keep them whole; or cut each at a limit, say where it was cut and that `read_segment` returns the rest, and put a placeholder for an image or a file. Recommendation: cut at a limit, because a Segment is meant to stay small for as long as the Session lives. To settle before Phase 6, step 1.
- [ ] **What a compaction a service asks for keeps as its tail.** A service compacts its idle Sessions through the compact endpoint until the warm Session (ROADMAP.md Phase 7), and today the endpoint keeps 4 Messages by default (`keep`). For a user who comes back, the latest Run is what they are most likely to ask about, tool results included. Options: keep `keep` as it is; or default to the rule of a tail kept mid-Run, the latest Run's Turns up to 20K tokens and a quarter of the window, cut at a Turn boundary. Recommendation: the mid-Run rule, so one rule sets every kept tail. To settle before Phase 6, step 1.
- [ ] **How the oldest Segments get their Recap when they merge on an overflow.** A merge asks the model for one Recap of the Recaps it merges. On an overflow, a request that holds the whole Context would be refused too. Options: a request that holds only the Recaps being merged, and when it fails, no merge and the Run ends with `context_overflow`; or a merge with no Recap. Neither Pi nor opencode v2 merges anything, so neither answers it. Recommendation: the Recaps alone, because that request is small, and a failure is told rather than hidden. To settle before Phase 6, step 4.
- [ ] **The model does not know how long the user was away.** A Segment carries its times, but the model is not told the time a new message arrives, so after days away it may answer as if no time had passed. A runtime notice could say it (FEATURES.md → G-F29), and so could the service in its own message. To settle with runtime notices (ROADMAP.md Phase 7).
- [ ] **Thirteen commits are kept only on the tag `archive/local-main-2026-09-23`.** They come from a local `main` of 2026-09-23 that was later rewritten, and none matches a commit on `main` by content. By name, most of their ideas exist on `main` in another form: `testkit.FuncModel`, the chat `reasoning_content` replay, the stream restarter, `MaxTruncatedContinuations`, and cache-read tokens in `Usage`. That is a check of names, not of the diffs. The optional `tools/` packages (`files`, `shell`, `git`) and the five `tools/shell` commits (sandbox rules and fixes) exist nowhere else; they sit against [FEATURES.md → G-N14](FEATURES.md#g-n14--no-remote-dev-environment-shell-or-sandbox-on-the-instances), which does not plan a shell or sandbox on the instances. Three commits are unchecked: storing streamed deltas as blocks, letting the model recover from bad tool calls, and per-request headers from the context. Decide for each whether to port it or let it go, then delete the tag.

## Open checks

- [ ] **Does a user who comes back after a compaction find the conversation they left?** GOALS.md G-E01 checks that the Recap keeps the facts, not that the conversation carries on: that the model answers a follow-up the way it would have before the compaction, in the same terms and without asking again what it was told. No goal measures it yet. A way to measure it is to be designed, as an evaluation next to G-E01.
- [ ] **Does `tool_choice: none` keep the prompt cache on Anthropic?** A Recap request that sends the tools but forbids calling them would stop a model from calling one ([FEATURES.md → G-F30](FEATURES.md#g-f30--a-last-turn-that-answers-)). Not run against the provider.
- [ ] **How long does a model-written Recap take?** It may take a minute or more, against `ModelCallDeadline` (2 minutes) and `RunDeadline` (5 minutes). Measure it on real models before the Recap is written mid-Run.
- [ ] **Does every refusal as too long reach the Loop before any output?** An Anthropic stream that ends with `model_context_window_exceeded` does so in the middle of a reply (`gateway/anthropic.go`), after some text, so a compact-and-send-again cannot assume no output. Check each wire API's path.
