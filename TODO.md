## Defects

- [ ] **`ToolUse.Executed` and `ToolUse.Result` are reserved and never assigned.** A Tool or `PreToolUse` extension always sees `false`/`nil`. Wire them into a `PostToolUse` view or remove them; removal changes the JSON shape and needs a breaking-change entry in `CHANGELOG.md` (`tool.go`).
- [ ] **Provider identity leaks into `ToolCall.ID`.** The Responses adapter packs the provider item ID into the call ID and splits it back with `splitResponsesCallID`, so a provider-private ID is persisted in the Session. Add an opaque, adapter-owned field to `ToolCall` (core clones and serializes it, like `ContentPart.Signature`) and keep `ToolCall.ID` to the call ID (`gateway/responses.go`, `types.go`).

- [ ] **`context_built` counts can arrive as strings.** The Agent merges the `ContextBuilder`'s metadata into the payload under the same keys, so `FullHistory`'s `"source_messages": "3"` replaces the Agent's `source_messages: 3`, and a consumer sees a string where the payload keys promise a count (`agent.go`, the `contextPayload` loop). Keep the Agent's own keys, or move builder metadata under its own key; either changes the payload and needs a `CHANGELOG.md` entry. `service/workload` reads both forms meanwhile.
- [ ] **A crash in the middle of a Run loses the whole Run.** `service.Runner` saves the Session once, after the Run settles (`service/service.go`, the `store.Save` after `agent.Prompt`). A pod that is killed or runs out of memory mid-Run loses every Turn the Run committed. `Drain` covers only a graceful shutdown. Save after each committed Turn.
- [ ] **Two pods can run one Session at once, and the last save wins.** The Session lock is local to one process (`withSessionLock`), and `Store.Save` replaces the whole document with no revision check. Two instances that share a Store can both run a Session and silently drop each other's Turns. A save must detect a concurrent write, and only one instance may run a Session at a time; a second instance must stop before it calls the model. The mechanism (a lease, a revision compared on save, or both) is an open question in DESIGNS.md. See DESIGNS.md → State and the store, GOALS.md G-G08 and FEATURES.md G-F27.

## Decisions

- [ ] **Typed event payloads (G-F13).** `Event.Payload` is `map[string]any` with documented keys, and the gRPC adapter carries it as `payload_json`. Choose between per-kind payload structs (a breaking wire change with a `ContractVersion` bump) and keys locked by tests. Add `reasoning_update` for streaming reasoning deltas either way; today only text deltas emit `message_update`.
- [ ] **A Session stops at 1,000 messages by default.** `CoreLimits.MaxMessages` (default 1,000) bounds the whole Transcript, not one Run. Once a Session holds 1,000 messages, every later Run fails with `limit_exceeded` when it commits the prompt, unless the Session is compacted or the service raises the limit. Automatic compaction is off by default, so a long-lived Session reaches this without warning. Options: count only the Run's own messages, raise the default, or document the limit next to compaction (`limits.go`, `commitMessage` in `agent.go`). The reference workload raises the limit for `history_1000` (`testkit.HistoryTask`).
- [ ] **A message's way into a Session has no Events (G-F13, G-F26).** Only the commit of a Steer or FollowUp is reported (`message_start`/`message_end` with `source`). Its arrival, a full buffer, a drop when the Run ends first (`discardControl` in `agent.go`), a Run rejected or waiting on a busy Session, a full Runner, and a cancel request emit nothing, so a team cannot see a lost message or measure how long a cancel takes. The names follow from what happens to a message mid-Run, so they are decided with DESIGNS.md → Open questions → What a warm Session holds; several steps come before any Run and may need a Runner-level stream.
- [ ] **Blocking `EventObserver` by default.** Every extension stage runs synchronously on the agent goroutine; `AdvisoryExtension` only makes a failure non-fatal. An observer doing I/O slows every event. Options: run observers asynchronously by default, add a per-call extension deadline, or document the cost and ship an async observer wrapper (`extensions.go`).
