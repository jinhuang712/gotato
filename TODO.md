## Defects

- [ ] **A crash in the middle of a Run loses the whole Run.** `service.Runner` saves the Session once, after the Run settles (`service/service.go`, `saveSession` after `live.Prompt`). An instance that is killed or runs out of memory mid-Run loses every Turn the Run committed. `Drain` covers only a graceful shutdown. Save after each committed Turn (ROADMAP Phase 4).
- [ ] **Two instances can run one Session at once, and the last save wins.** The Session lock is local to one process (`withSessionLock`), and `Store.Save` replaces the whole document with no revision check. Two instances that share a Store can both run a Session and silently drop each other's Turns. A save must detect a concurrent write, and only one instance may run a Session at a time; a second instance must stop before it calls the model. The mechanism is decided: an append-only Record, a Claim with an Epoch checked on every append, and one Liveness row per instance (DESIGNS.md → The Record is an append-only log, and One writer per Session, both 2026-10-16; ROADMAP Phases 4 and 5). See GOALS.md G-G08 and FEATURES.md G-F27.

## Decisions

- [ ] **Reasoning is replayed to whichever model runs the next Turn.** A reply records the model that answered it (`Message.Model`), but nothing reads it yet, so a Session whose model changes sends the old model's reasoning artifacts to the new one. The model can change at any request, not only with a new `service.Agent.Model`: a gateway in front of the providers may fall back to another model, or follow priorities set in its own portal. On 2026-10-16 the Responses API accepted `gpt-6.1-sol`'s encrypted reasoning in a request to `gpt-6-luna` without an error. Anthropic was not tested; its thinking signatures may be refused by another model. If they are, the gateway can tag each artifact it stores with its wire API and model (the artifact is adapter-owned) and drop a mismatched one on replay (`gateway/anthropic.go`, `gateway/responses.go`).
- [ ] **Typed event payloads (G-F13).** `Event.Payload` is `map[string]any` with documented keys, and the gRPC adapter carries it as `payload_json`. Choose between per-kind payload structs (a breaking wire change with a `ContractVersion` bump) and keys locked by tests. Add `reasoning_update` for streaming reasoning deltas either way; today only text deltas emit `message_update`.
- [ ] **A Session stops at 1,000 messages by default.** `CoreLimits.MaxMessages` (default 1,000) bounds the whole Transcript, not one Run. Once a Session holds 1,000 messages, every later Run fails with `limit_exceeded` when it commits the prompt, unless the Session is compacted or the service raises the limit. Automatic compaction is off by default, so a long-lived Session reaches this without warning. Options: count only the Run's own messages, raise the default, or document the limit next to compaction (`limits.go`, `commitMessage` in `session.go`). The reference workload raises the limit for `history_1000` (`testkit.HistoryTask`).
- [ ] **A message's way into a Session has no Events (G-F13, G-F26).** Only the commit of a Steer or FollowUp is reported (`message_start`/`message_end` with `source`). Its arrival, a full buffer, a drop when the Run ends first (`discardControl` in `session.go`), a Run rejected or waiting on a busy Session, a full Runner, and a cancel request emit nothing, so a team cannot see a lost message or measure how long a cancel takes. What happens to a message mid-Run is now decided (FEATURES.md → G-F26 → Messages that arrive during a Run), so the names are the open question, designed at the start of ROADMAP.md → Phase 6.
- [ ] **Blocking `EventObserver` by default.** Every extension stage runs synchronously on the agent goroutine; `AdvisoryExtension` only makes a failure non-fatal. An observer doing I/O slows every event. Options: run observers asynchronously by default, add a per-call extension deadline, or document the cost and ship an async observer wrapper (`extensions.go`).
