# Changelog

What changed in Gotato, from the user's side. Newest first. A breaking change carries a before/after note, so you can move your code in one pass. Additive changes may be listed, but breaking ones must be.

## Unreleased

### Breaking

- **`gotato.ModelConfig` is now the model's description, and the sampling struct is `gotato.Sampling`** (D-045).
  - Before: `gotato.ModelConfig{Temperature, MaxTokens, ReasoningEffort, ReasoningSummary}` was the sampling and reasoning hints of a call.
  - After: `gotato.ModelConfig{Name, Facts ModelFacts, Sampling Sampling}` describes one model. The four sampling fields moved to `gotato.Sampling`, and `ModelFacts{Window, CacheRetention, RoundReasoning, ThinkingBinding}` is what the model is. Rename `gotato.ModelConfig{Temperature: ...}` to `gotato.Sampling{Temperature: ...}`.
- **`gotato.Model` gains `Config() ModelConfig`; every Model written by hand must add it.**
  - Before: a Model was one method, `Stream`.
  - After: a Model is `Stream` and `Config`, and your code no longer compiles until you add the method. Returning the zero `gotato.ModelConfig` is valid: the window reads as unknown, so compaction has no ceiling trigger and runs only after the provider refuses a request as too long; no cache retention; no default sampling. A wrapper that embeds a Model has `Config` already; one that holds it in a field returns `m.Inner.Config()`. `testkit`'s fakes and the gateway's Client implement it.
- **`WithModelConfig` is `WithSampling`, and `ModelRequest.Config` is `ModelRequest.Sampling`.**
  - Before: `gotato.WithModelConfig(gotato.ModelConfig{Temperature: &t})`; `ModelRequest.Config`, `"config"` in its JSON.
  - After: `gotato.WithSampling(gotato.Sampling{Temperature: &t})`; `ModelRequest.Sampling`, `"sampling"` in its JSON. The Model's own default (`Config().Sampling`) sits under the Session's: each field `WithSampling` leaves unset keeps the Model's default, and `ModelRequest.Sampling` carries the result. A wrapper or a fake that read `request.Config` reads `request.Sampling`.
- **`Window`, `WindowTokens` and `WindowUnknown` moved from `gateway` to `gotato`.**
  - Before: `gateway.Window`, `gateway.WindowTokens(200_000)`, `gateway.WindowUnknown()`.
  - After: `gotato.Window`, `gotato.WindowTokens(200_000)`, `gotato.WindowUnknown()`, in `ModelFacts.Window`. A `Window` reads and writes as text (the number, or `unknown`) in JSON and YAML. `gateway.New` still refuses a window that is not stated.
- **The model capability probes are deleted; the core reads `Model.Config().Facts`.**
  - Before: `modelctx.ContextWindower`, `CacheRetainer`, `RoundReasoner`, `Unwrapper`, `modelctx.WindowOf`, `RetentionOf`, `DropsReasoning`, and the Client methods `ContextWindowTokens()`, `CacheRetention()`, `RoundReasoningOnly()` and `DeferredTools()`. A wrapper that forgot `Unwrap` hid the window, and the ceiling with it.
  - After: none of them exists. The Runner and compaction read `Model.Config().Facts` (`Window`, `CacheRetention`, `RoundReasoning`), and a wrapper that embeds a Model forwards `Config` for free. Replace `modelctx.WindowOf(m)` with `m.Config().Facts.Window.Tokens()`, `RetentionOf(m)` with `m.Config().Facts.CacheRetention`, and `DropsReasoning(m)` with `m.Config().Facts.RoundReasoning`; delete your `Unwrap` and capability methods. `Client.Config()` replaces the Client methods; the deferred form is the `Deferred` field of the wire.
- **`gateway.New` takes a wire API, a connection and a model, and the gateway is four layers.**
  - Before: `gateway.New(gateway.Config{API: gateway.APIAnthropicMessages, Model: "a-model", APIKey: key, BaseURL: "https://gateway.example.com/v1", ...})`, one flat struct.
  - After:

    ```go
    client, err := gateway.New(
        gateway.AnthropicMessages{},                      // the wire API
        gateway.Connection{Endpoint: "https://gateway.example.com/v1/messages", APIKey: key},
        gotato.ModelConfig{Name: "a-model", Facts: gotato.ModelFacts{Window: gotato.WindowTokens(200_000)}},
        gateway.WithRetry(gateway.DefaultRetry),          // options: WithRetry, WithClassifier
    )
    ```

    The layers are the wire API (`gateway.WireAPI` with `Encode(Call) (*Request, error)`; the shipped `ChatCompletions{CacheKeyField}`, `Responses{CacheKeyField, Deferred}` and `AnthropicMessages{Version, Deferred}`), the `Connection` (`Endpoint`, `APIKey`, `CacheKeyHeader`, `Headers`, `HTTPClient`), `Retry` and the `Classifier` (`Failure`, `Verdict{Retryable, Overflow, Limit}`, `DefaultClassifier`, `WithClassifier`). Each has a default and can be replaced. A new wire API is one type of your own; any authentication beyond a key goes in the `RoundTripper` of `Connection.HTTPClient`.
- **Gotato no longer recognizes a provider from its address or a model from its name; the team states the facts.**
  - Before: an endpoint at a recognized Claude or OpenAI address got only the current Round's reasoning, the longest cache retention (1 hour on Claude, 30 minutes on Responses) and `block_binding` chosen by model name; any other address got none of that.
  - After: none of it is derived. A team sets `ModelFacts.RoundReasoning` (the provider takes back only the current Round's reasoning), `ModelFacts.CacheRetention` (the Anthropic wire asks for the ttl `1h` from 1 hour, the Responses wire sends `prompt_cache_options` with `30m` for exactly 30 minutes) and `ModelFacts.ThinkingBinding` (the Anthropic wire sends `block_binding: drop_block` with its beta header). A team that omits them sends more reasoning and gets the provider's default retention; a provider accepts both, so nothing fails, and a team that relied on the old recognition sets the facts to keep its bytes and its cache savings. `officialHosts`, `thinkingPrefixModels` and the `Provider` type are gone.
- **`gateway.Config`, flat `New`, `NewWithProfile`, `ModelProfile`, `ProfileSet`, `Provider` and `LoadYAML` are removed; the YAML file moved under `internal/cmd`, with new keys.**
  - Before: `gateway.LoadYAML(path)` returned a `Config`; `gateway/gateway.example.yaml` was the file to copy.
  - After: a service builds its Client in Go with `gateway.New`. Only Gotato's test tools read a file (`gotato --gateway-config`, `gotato-workload -gateway-config`, `examples/larkbot`), through `internal/cmd/gatewayconf`, which a program outside the module cannot import; the file to copy is `internal/cmd/gatewayconf/gateway.example.yaml`. Key changes: `base_url` and `endpoint` are one `endpoint`, the complete URL with its path; `context_window_tokens` is `window`, a number or `unknown`, and is required; `provider` and `no_drop_block` are gone; `cache_retention` is now a fact, with no default; new keys `round_reasoning`, `thinking_binding`, `temperature`, `max_tokens`, `reasoning_effort`, `reasoning_summary` and `anthropic_version`; `max_retries: 0` turns retries off (it was `-1`); `overflow_phrases`, `retry_backoff`, `max_retry_wait`, `connect_timeout`, `response_header_timeout`, `headers`, `cache_key_field`, `cache_key_header` and `deferred_tools` stay.
- **`Connection.BaseURL`, the timeout fields and `MaxRetries`, `RetryBackoff`, `MaxRetryWait` are removed.**
  - Before: `BaseURL` (the gateway added the path), `ConnectTimeout`, `ResponseHeaderTimeout`, `MaxRetries` (`-1` for none), `RetryBackoff`, `MaxRetryWait` on `Config`.
  - After: `Connection.Endpoint` is the complete URL, path included (`https://gateway.example.com/v1/chat/completions`). `gateway.NewHTTPClient(connect, header)` makes a client with timeouts (10 s and 60 s when `HTTPClient` is nil). `gateway.WithRetry(gateway.Retry{Max, Backoff, MaxWait})` sets the retries: `gateway.DefaultRetry` is 2, 200 ms, 60 s, and `gateway.Retry{}` is off.
- **`OverflowPhrases` is gone: wrap `DefaultClassifier`.**
  - Before: `Config.OverflowPhrases: []string{"too_much_context"}` added a team's wording for "the request was too long".
  - After: `gateway.WithClassifier(func(f gateway.Failure) gateway.Verdict { v := gateway.DefaultClassifier(f); if strings.Contains(f.Message, "too_much_context") { v.Overflow, v.Retryable = true, false }; return v })`. The file's `overflow_phrases` still works in the test tools.
- **The Responses wire no longer refuses an empty key.**
  - Before: `openai-responses` with an empty `APIKey` was refused when the Client was built.
  - After: an empty key sends no credential on every wire, as chat and Anthropic already did, so a keyless local server works over Responses.
- **A mid-stream error that says rate limit is retryable, a cut stream says "stream interrupted" on every wire, and the Anthropic version has an order.**
  - Before: an error the provider sent mid-stream was marked `Retryable` only by its code or type; a cut stream was worded for its wire (`ended before message_stop` on Anthropic, for instance); the `anthropic-version` was `2023-06-01` unless a header named it.
  - After: such an error whose text says rate limit, overloaded or service unavailable is `Retryable` too, like a refused request (the gateway still does not send it again). A cut stream is reported as `stream interrupted` on every wire, so anything that matched the wire-specific text breaks. The `anthropic-version` is `AnthropicMessages.Version`, else a header the Connection sets, else `2023-06-01`. An Overflow verdict is never `Retryable`.
- **The conformance suite is one function for each seam, and a Liveness check can move the clock.** `storetest.Run` and `storetest.Check` are replaced by `RunRecords`, `RunLiveness` and `RunLister` (and `CheckRecords`, `CheckLiveness`, `CheckLister`), each with its own backing; a `Load` racing appends is checked; `RunLiveness` takes an optional `storetest.WithAdvance` that replaces its sleeps. `session.NewMemoryStore` and `session.NewFileStore` take `session.WithClock`, which times their Liveness rows.
  - Before: `storetest.Run(t, func() (storetest.Open, func(), error) { … return func() session.Store { … } … })` ran every check against one `session.Store`, and a test that needed a row to expire slept; `NewMemoryStore()` and `NewFileStore(dir)` always used the machine's clock.
  - After: `storetest.RunRecords(t, backing)` with a `func() session.Records` per handle, `storetest.RunLiveness(t, backing)` with a `func() session.Liveness`, and `storetest.RunLister(t, backing)` for a `Records` that implements `session.Lister` (an adapter with no `Lister` does not call it). `session.NewMemoryStore(session.WithClock(clock.Now))` and `session.NewFileStore(dir, session.WithClock(clock.Now))` move with a fake clock.
- **`Runner.Sessions` takes a `ListQuery` and returns a `ListPage`, and `GET /v1/sessions` takes `limit` and `cursor`.** `ListOption` is gone. The listing items no longer carry `record_epoch`.
  - Before: `list, err := runner.Sessions(ctx)` returned every `session.RecordInfo`, and `GET /v1/sessions` answered a JSON array of Session summaries, each with `record_epoch`, `seq`, `running`, `busy`, `notices` and `last_run_end`.
  - After: `page, err := runner.Sessions(ctx, session.ListQuery{Limit: 50, Cursor: next})` returns a `session.ListPage{Infos, Next}`, 100 Sessions at most when `Limit` is 0, and `not_supported` when the store's `Records` is not a `session.Lister`. `GET /v1/sessions?limit=50&cursor=…` answers `{"sessions": […], "next": "…"}` with `next` left out after the last page; each item holds the listing columns only (`id`, `parent_id`, `created_at`, `updated_at`, `messages`, `runs`, `usage`, `metadata`). `POST /v1/sessions` and `…/fork` still answer the summary with `record_epoch`. A client that listed Sessions as an array reads `sessions` and follows `next`; one that read `running` or `busy` from the list asks the Session, or keeps its own columns.
- **An Entry's stored Layer comes from one table, and an unlisted kind fails.** Every stored Event kind is listed once with its Layer in `session`, and `entryOf` returns an error for a stored kind that has none.
  - Before: a kind not in the list of facts was silently a log Entry, so a new Event kind that a rebuild needed, if it was forgotten there, was dropped from every load.
  - After: a kind with no Layer fails the write with `internal_invariant`, and a test ranges over every stored kind to keep the table whole. Only a Gotato change that adds a stored Event kind can meet it.
- **The Header carries the Record's columns apart from Gotato's state, and a load is one read.** A write passes `session.Header{Epoch, Info, State, LogFrom}`; `RecordInfo` keeps listing columns only; `Load` returns `Loaded{Entries, Segments, Seq, Header}`.
  - Before: `RecordInfo` also held `RecordEpoch`, `Seq`, `Running`, `Busy`, `LastRunEnd` and `Notices`; `Create(ctx, id, entries, info)` and `Append(ctx, id, after, entries, info)` took it; `Load` returned `Loaded{Facts, Segments, Head, Info}`; a rebuild of a Record with a Run in flight called `Load` and then `Log`, and returned `ErrConflict` when the Record moved between the two.
  - After: `Create(ctx, id, entries, h session.Header)` and `Append(ctx, id, after, entries, h)`. `Header.Epoch` is the Record epoch (`Info.RecordEpoch` is gone), `Header.Info` the listing columns, `Header.State` Gotato's own JSON (the Run in flight, busy, notices, the last Run end, the counts a load starts from), which an adapter keeps whole and never reads, and `Header.LogFrom` the position from which `Load` also returns log Entries, which the Writer sets to the last Checkpoint's position while a Run is in flight. `Loaded.Entries` are the facts from the last Checkpoint plus every Entry from `LogFrom`, `Loaded.Seq` replaces `Head`, and `Loaded.Header` replaces `Info`, all from one read, so opening a Writer calls `Load` once and `Log` never, and has no `ErrConflict` path. Move an adapter's columns for `RecordEpoch` to the Header's `Epoch`, store the Header as a whole (its JSON) next to the columns it indexes, and have `Load` apply `LogFrom`. The `FileStore` writes `{"entries", "header"}` in each batch file instead of `{"entries", "info"}`: a directory written by an earlier build is not read, so start from an empty one.
- **`session.Store` is two seams and a struct, and listing is optional.** `Store` is `struct{ Records Records; Liveness Liveness }`; `Records` has `Create`, `Append`, `Load`, `Log` and `Delete`; `Liveness` has `Beat` and `Instance`; `session.Lister` has `List(ctx, ListQuery) (ListPage, error)` and is found as `store.Records.(session.Lister)`.
  - Before: `Store` was an interface with eight methods, `Liveness` embedded in it, and `List(ctx) ([]RecordInfo, error)` was required, with no paging; two databases needed a hand-written composite; `service.Config{Store: store}` took the `*MemoryStore` or `*FileStore` itself; `session.CreateWriter`, `OpenWriter`, `Open`, `View` and `StoredEvents` took a `session.Store`.
  - After: `service.Config{Store: session.Store{Records: store, Liveness: store}}` (a `*MemoryStore` and a `*FileStore` are all three), or `Records` and `Liveness` from two databases; `CreateWriter`, `OpenWriter`, `Open`, `View` and `StoredEvents` take a `session.Records`; an adapter drops `List` unless the service lists Sessions, and then writes it with a cursor. `Records` gains no methods after 0.3.0. A wrapper of `Records` must pass on `List` itself to stay a `Lister`.
- **A store's ID and batch checks are exported, and the file-name limit belongs to `FileStore`.** `session.CheckID(id)` and `session.CheckBatch(after, entries, ...)` are what every store calls, and `session.MaxNameBytes` is gone.
  - Before: the checks were unexported, so an adapter copied them (the guide's copy included), and every store, `MemoryStore` and an adapter's too, refused an ID whose file name would pass 200 bytes: 23 CJK characters (69 bytes) were `ErrInvalidID` everywhere.
  - After: an adapter calls `session.CheckID` and `session.CheckBatch`, and a store may refuse more IDs with `ErrInvalidID`. Only `FileStore` refuses a file name over 200 bytes; `MemoryStore` and a database adapter keep those IDs. Delete the adapter's copies, and any use of `session.MaxNameBytes`.
- **An Event's Run is stamped when the Event is numbered, so no Event of a Run falls outside it.** A `message_queued`, `notice_queued`, `message_dropped` or `message_rejected` that is written outside a Run has no `run_id`, and an `abort_requested` always follows its Run's `run_started`.
  - Before: these Events took the Run's `run_id` when the call was made, not when the Event was written: a Steer from `WithRunStart` or just as a Run ended was stored with the Run's ID before its `run_started` or after its `run_ended`, and an Abort in `WithRunStart` stored `abort_requested` before `run_started`.
  - After: such a Steer or Notice is stored with an empty `run_id`; an Abort before `run_started` is written is stored right after it, in the same write, under the Run. A consumer that read the Run of a `message_queued` as the Run it was sent to should read the Run that takes it from `message_committed`.
- **A Tool of your own cannot take a name under a ToolSet's namespace.** The ID and the `Name` of a Tool from `WithTools` or a `ToolSource` may not start with the name of an installed ToolSet and a dot. A dotted name outside every namespace, like `payments.get_batch`, is still yours.
  - Before: `WithTools` with a Tool `files.read` and a ToolSet `files` started, then failed every Run once the ToolSet, installed active, carried `read`; a root Tool with `Name: "files.read"` ran in place of the ToolSet's `files.read` when the Model called it.
  - After: `NewSession` fails with `invalid_argument`; a `ToolSource` that supplies such a Tool keeps its last set and stores `extension_failed` (stage `toolsource`), and the Run goes on. Rename the Tool, for example `local_read`.
- **A service Agent whose tools repeat a Tool ID is refused.** `Agent.Tools`, `Agent.ToolSources`, `read_result` and `read_segment` are one tool source to the Session, and a repeated ID fails it like any bad Tool.
  - Before: the first Tool with the ID was kept and the other was dropped without a word, so an Agent's own `read_result` hid the built-in one.
  - After: a Run of the Agent fails with `invalid_argument` (or, when a `ToolSource` starts repeating an ID mid-Session, the Session keeps its last set and stores `extension_failed`, stage `toolsource`), and `Runner.Tools` fails with `invalid_argument`. Give each Tool its own ID.
- **`search_tools` is a reserved Tool name.** A Tool of your own may not have it as its ID or its `Name`.
  - Before: a root Tool `search_tools` worked while no ToolSet offered a catalog, then failed every Run once one did.
  - After: `NewSession` fails with `invalid_argument`; a `ToolSource` that supplies one keeps its last set, as above.
- **`inspect` always reports `compact_ceiling_tokens`.** The Report of `modelctx`, the CLI's `context inspect --json` and the HTTP endpoints carry the field with 0 when the ceiling trigger is off (no context window and no `CeilingTokens`), and the text output says `compact_ceiling_tokens 0 (off: compacts only after a refusal as too long)`.
  - Before: `compact_ceiling_tokens` was left out of the JSON when it was 0, so a program could not tell "off" from "not reported".
  - After: the key is always there; 0 means off. A consumer that tested for the key to know a ceiling was set should test for a value above 0.
- **The `search_tools` result names what it did not load as an instruction.** The line for tools that were found but not loaded changed.
  - Before: `Also found, not loaded: a, b.`
  - After: `Found but not loaded, so do not call them yet; call search_tools with these names first: a, b.` Anything that matches the old text (a test, a log filter, a parser of the result) breaks.
- **A failed Tool Result has a `Code`, and there is a new error code `tool_not_loaded`.** `gotato.CodeToolNotLoaded` (`tool_not_loaded`) is the Code of a call to a catalog Tool the Model had not loaded: the call did not run, the Tool is loaded now, and the Model may call it again.
  - Before: `ErrorCodes()` had no such code, and a failed `ToolResult` and its `tool_ended` had no code: the reason was a prefix of `SafeError`.
  - After: `ErrorCodes()` lists `tool_not_loaded`, and `ToolResult.Code` and `ToolEnded.Code` (`code` in JSON, left out when empty) hold `tool_resolution_failure`, `tool_argument_failure`, `tool_execution_failure`, `deadline_exceeded` or `tool_not_loaded` on a failed call. A switch over `ErrorCodes()` needs a case for the new code (the CLI exits with the generic error status and the HTTP API answers 500 for it). A result stored before the field existed, and a blocked call, have none.
- **The chat wire fills `CacheWriteTokens` and reads `cache_read_input_tokens`.** For `openai-chat-completions`, behind a gateway that passes Anthropic's usage fields through.
  - Before: `CacheWriteTokens` was always 0 on chat and `cache_read_input_tokens` was not read, so those tokens were counted as plain input.
  - After: `cache_creation_input_tokens` goes into `CacheWriteTokens` (capped at the input that is not a cache read), and `cache_read_input_tokens` into `CacheReadTokens` (the larger of it and the other cache counts, capped at the input). A cost sum over `Usage` changes for such a gateway: price the cache parts at their own rates, as in [FEATURES.md](FEATURES.md).
- **`service.Agent.Options` is gone; its uses are typed fields, and the Runner builds every `SessionOption`** (D-047).
  - Before: `service.Agent{Options: []gotato.SessionOption{gotato.WithToolSet(set), gotato.WithExtension(x), gotato.WithSampling(s)}}`. The options ran after the Runner's own, so one could replace the Writer, set a cap that `Runner.Tools` did not see, or put back a tool a Session had switched off.
  - After: `service.Agent{ToolSets: []service.ToolSet{{Set: set, Mode: service.ToolSetListed}}, Extensions: []any{x}, Sampling: s, ToolSearcher: searcher}`. `Mode` is `ToolSetListed` (the default), `ToolSetFolded` or `ToolSetActive`, for `WithToolSet`, `WithFoldedToolSet` and `WithActiveToolSet`. `New` refuses a nil ToolSet, an unknown Mode and a nil Extension. A caller that set anything else through `Options` (`WithMaxEffect`, `WithInstruction`, `WithTranscript`) uses the Agent's own field (`MaxEffect`, `Instruction`) or has none: the Runner owns the rest. `reftasks.Task.Options` became `ToolSets` for the same reason.
- **A Session metadata key under `gotato.` is the Runner's, and a caller that sets one is refused; the `Meta*` constants are unexported.** `service.ReservedPrefix` is `"gotato."` and `service.ErrReservedKey` is `invalid_argument`, not run.
  - Before: `CreateSession`, `RunRequest.Metadata`, `RunRequest.Update` and `POST /v1/sessions` took any key, so a remote caller could replace the instruction (`gotato.instruction`), move the compaction ceiling (`gotato.compact_ceiling`), switch the Agent (`gotato.agent`), switch a tool (`gotato.tool.<id>`) or change the cache key. `service.MetaAgent`, `MetaInstruction`, `MetaCompactCeiling`, `MetaModel`, `MetaCacheKey` and `MetaToolPrefix` were exported.
  - After: each of those calls fails with `ErrReservedKey`, naming the key, before anything is written (HTTP: 400 `invalid_argument`, `not_run`). The Agent changes only by `RunRequest.Agent` (an `Update` of `gotato.agent` is refused, not applied), a tool switch only by `Runner.SetToolActive`, the cache key only by `Runner.Fork`. The constants are unexported; read a key from a Record's metadata as `service.ReservedPrefix + "agent"` (`"gotato.agent"` on the wire). The Runner no longer reads `gotato.instruction` or `gotato.compact_ceiling`: a stored one is ignored (no migration). A Session has no instruction or ceiling of its own, so register another Agent (an `Instruction`, a `Compact.CeilingTokens`) and name it in `RunRequest.Agent`. The CLI's `--instruction` and `--compact-ceiling` select a variant of the built-in Agent in the same way, and its name carries the definition.
- **`NewSession` refuses a single-valued option given twice.**
  - Before: `gotato.NewSession(ctx, WithTranscript(a), WithTranscript(b))`, `WithInstruction`, `WithMaxEffect`, `WithToolFilter`, `WithSampling` and the like took the last one in silence.
  - After: it fails with `invalid_argument` naming the option (`WithTranscript was given twice; a Session has one`). The single-valued options are `WithModel`, `WithInstruction`, `WithSampling`, `WithCacheKey`, `WithMaxEffect`, `WithLimits`, `WithContextBuilder`, `WithToolFilter`, `WithTranscript`, `WithToolSearcher`, `WithFeed`, `WithRequestID`, `WithRunStart` and `WithQueueHandoff`. `WithTools`, `WithToolSource`, `WithExtension` and the ToolSet options add, and may be given again.
- **A `gotato.Transcript` declares its capabilities, and `NewSession` refuses a durable one that lacks a part.** `Transcript` gains `Capabilities() gotato.Capabilities`; every Transcript written by hand must add it.
  - Before: a Transcript's Journal, `Durable() bool`, `gotato.SpillKeeper` (`KeepsSpilledResults() bool`), `EventSource`, `LoadedToolSource` and `ID() string` were found by type assertion, so a wrapper that forgot one lost durability, spilling or the loaded Tools without an error.
  - After: `Capabilities() gotato.Capabilities{ID string; Journal Journal; Durable, Spill bool; Events EventSource; Loaded LoadedToolSource}`. `gotato.SpillKeeper` and the optional `Durable()` method are gone. A wrapper that embeds the concrete type (`session.Record`, `session.Writer`) forwards it; any other wrapper writes the declaration, and `Capabilities{}` is a Transcript that stores nothing (the default in-memory one). `NewSession` fails with `invalid_argument` for `Durable` without `Journal`, `Events` and `Loaded`. `session.Record`, `session.Writer` and the Runner's transcript for a Run that is not saved declare theirs.
- **`Runner.CreateSession` takes a request and answers a value; `CreateSessionExclusive` is gone; `Fork` and `Record` answer values; `Runner.Store()` is removed.**
  - Before: `s, err := runner.CreateSession(ctx, "agent", metadata, session.WithID(id), session.WithMessages(history...))` and `runner.CreateSessionExclusive(ctx, agent, id, metadata)` returned a `*session.Record` whose `Set` was stored nowhere; `Fork` returned a `*session.Record`; `Record` returned a `*session.Record`; `runner.Store()` returned the Store.
  - After: `info, err := runner.CreateSession(ctx, service.CreateSessionRequest{Agent: "agent", ID: id, Metadata: metadata, Messages: history})` returns a `session.RecordInfo` (`info.ID` is a field), and a taken ID is `ErrSessionExists`; `Fork` returns a `session.RecordInfo`; `Record` returns a `session.Document`, a copy (`doc.Metadata`, `doc.Messages`, `doc.Seq` for the head). To read what a Document does not hold (a Claim, whether the Session is held), read the Record through the Store you gave to `service.New`: `session.View(ctx, store.Records, id)`. `POST /v1/sessions` and `GET /v1/sessions/{id}` keep their wire shapes.
- **The ref form moved to the public package `ref`** (D-046).
  - Before: the ref helpers lived in `internal/text`; the tool IDs were `modelctx.ReadResultID` and `modelctx.ReadSegmentID`.
  - After: `ref.Result(call)` and `ref.Message(id)` return a `ref.Ref{Kind, ID}` whose `String()` is `result:<id>` or `msg:<id>`; `ref.Parse`, `ref.Safe`, and the constants `ref.ReadResult`, `ref.ReadSegment`, `ref.ResultPrefix` and `ref.MessagePrefix`. Replace `modelctx.ReadResultID` with `ref.ReadResult` and `modelctx.ReadSegmentID` with `ref.ReadSegment`. The form is a contract, since Segments carry it forever.
- **A Session spills a Tool Result only with a `ReadBack`, and the page size has one owner.**
  - Before: `gotato.SpillPageBytes` (32 KiB) and `gotato.SpillPreviewBytes` were constants and `gotato.ReadResultToolID` named the tool in every preview, installed or not; `ReadResultConfig.PageBytes` and `ReadSegmentConfig.PageBytes` set another page for the read tools.
  - After: all four are gone. `gotato.WithReadBack(rb)` installs a `gotato.ReadBack` (a `ToolSource` with `PageBytes() int`; the last call wins); the spill threshold, the pages a preview counts and both read tools use its one `PageBytes`. `NewSession` asks it once and refuses a value below 1, or a panic, with `invalid_argument`. A Session spills only with a `ReadBack` installed and a Transcript that keeps spilled results (`Capabilities.Spill`); without them a result is committed whole. `CoreLimits.SpillPreviewBytes` (default 8000, never above the page) sets the preview, and the core writes the ref line.
- **The read tools are a `ReadBack` over `Originals`.**
  - Before: `modelctx.ReadResultTool`, `ReadSegmentTool`, `ResultTools`, `SegmentTools`, `ReadResultConfig` and `ReadSegmentConfig`, each built over a Record.
  - After: all are gone. `modelctx.ReadBack{Originals, PageSize, Location}` implements `gotato.ReadBack` and offers `read_result` always and `read_segment` once the Context holds a Segment (always, when its `Originals` does not also have `Segments() []gotato.Segment`). `modelctx.Originals` is `Ref(ctx, ref.Ref) (gotato.Message, error)` and `Segment(ctx, n int) ([]gotato.Message, bool, error)`, with `ErrNoOriginal` (which may carry `Hint() string`) and `ErrRemoved`; `modelctx.RecordOriginals(record, log)` is the default. Use `gotato.WithReadBack(modelctx.ReadBack{Originals: modelctx.RecordOriginals(record, log)})`. IDs, paging, escaping, the read Effect and wording are unchanged, except that a pruned body now reads `<ref> was removed from the Record, so only what the conversation keeps of it is left.`, for results and messages alike.
- **`Record.CloseSegmentAndCheckpoint` is `Record.CloseSegment`.**
  - Before: `CloseSegmentAndCheckpoint(why, segment, earlier, tail, compaction)`; the caller listed the earlier Segments and set the loaded Tools with `SetLoadedTools`.
  - After: `CloseSegment(why, segment, tail, compaction)`. The Record lists every Segment of the Context itself, so a caller cannot drop or move one, and sets the loaded Tools from `Compaction.LoadedTools` in the same step. `Record.SetLoadedTools` still exists.
- **`Compact` and `AutoCompact` take a `SegmentStore` and a `Compactor`; `CompactConfig`, `CompactPolicy` and `SegmentSettings` lost fields; `MergeConfig` is gone.**
  - Before: `modelctx.Compact(ctx, record, cfg, opts...)` with a `CompactConfig` that embedded `CompactPolicy`; `modelctx.AutoCompact(record, policy)`; `CompactPolicy{Recap, SegmentSettings, ...}` and `CompactPolicy.Validate`; `SegmentSettings{TailTokens, Location, ...}`; `modelctx.MergeConfig`.
  - After: `modelctx.Compact(ctx, store, compactor, cfg, opts...)` and `modelctx.AutoCompact(store, compactor)`, where `store` is a `modelctx.SegmentStore` (`*session.Record` is one) and `compactor` a `modelctx.Compactor{CompactPolicy, Trigger, Cut, Builder, Recap, Merge}`; a nil part is its default, so `modelctx.Compactor{}` is the old behaviour. `CompactPolicy` keeps only numbers: `CeilingTokens`, `WindowTokens`, `DropReasoning`, `SegmentBudgetTokens`, `Location`. `Recap` moved to `Compactor.Recap`, `SegmentSettings` (now with `MessageTokens`, `ToolLines`, `ArgChars` only) to `CodeSegments{SegmentSettings}`, `TailTokens` to `TailBudget.TailTokens`, `Location` to `CompactPolicy.Location`, `Validate` to `Compactor.Validate`. `CompactConfig` is `{CompactPolicy, KeepMessages, MinTokens, Recap}`: non-zero numbers replace the Compactor's for the call, `KeepMessages` replaces the Cutter with `TailBudget{KeepMessages}`, and `Recap` replaces the writer. `MergeConfig` and the package-level `closeSegment` and `mergeSegments` seams are removed.
- **`modelctx.RecapWriter` has two more methods.**
  - Before: `Name` and `WriteRecap`; the service matched `ModelRecap` by type to give it the Agent's model.
  - After: also `WithAgentModel(gotato.Model) RecapWriter` and `Validate() error`, so a custom writer must add both (a writer that wraps a `ModelRecap` passes the model on, and one that asks no model returns itself and `nil`). The service gives every writer the Agent's Model through `WithAgentModel` and no longer matches `ModelRecap` by type.
- **`service.Agent.Compact` is a `modelctx.Compactor`.**
  - Before: `Compact: modelctx.CompactPolicy{Recap: modelctx.ModelRecap{}}`; `Runner.Compact(ctx, id, modelctx.CompactConfig)` ran the policy.
  - After: `Compact: modelctx.Compactor{Recap: modelctx.ModelRecap{}}`; `Runner.Compact` runs the Agent's Compactor with the per-call overrides of the `CompactConfig`.
- **The service installs the default `ReadBack`, and offers `read_result` by the Agent's configuration.**
  - Before: the service added its own read tools, and offered `read_result` by the tools actually offered after the Effect cap and the Session's switches.
  - After: the service installs `modelctx.ReadBack` over its store with `gotato.WithReadBack`, and offers `read_result` when the Agent has a Tool, a ToolSource or a ToolSet, or a Segment exists, which is steadier for the cache.
- **`Events`, `StreamRun`, `StreamRunAdmitted` and `StreamSession` take no options tail** (D-048).
  - Before: `runner.Events(ctx, id, opts...)`, `StreamRun(ctx, req, sink, opts...)`, `StreamRunAdmitted(ctx, req, admitted, sink, opts...)` and `StreamSession(ctx, id, from, opts...)` ended with `...EventsOption`, `...StreamRunOption` and `...SessionStreamOption`, types that held no option.
  - After: the three types are gone and the calls end at their last argument. A caller that passed no option compiles as before; adding an option later is a break with its own entry. `AbortSession` keeps `...AbortOption` (`AbortRun` exists).

- **The settings struct `service.Liveness` is `service.Heartbeat`, and `Config.Liveness` is `Config.Heartbeat`** (D-048).
  - Before: `service.Config{Liveness: service.Liveness{TTL: 10 * time.Second, Wait: 5 * time.Second}}`.
  - After: `service.Config{Heartbeat: service.Heartbeat{TTL: 10 * time.Second, Wait: 5 * time.Second}}`. The fields and their defaults are the same; the name no longer collides with `session.Liveness`, the store seam that keeps the rows.

- **Whether a Run may start is the `Admitter`'s decision; `MaxActiveRuns` moved out of `service.Admission`, and the rest of that struct is `service.Bounds`** (D-048).
  - Before: `service.Config{Admission: service.Admission{MaxActiveRuns: 8, MaxActiveSessions: 100, MaxWarmSessions: 5000, Queue: service.QueuePolicyWait}}`.
  - After: `service.Config{Bounds: service.Bounds{MaxActiveSessions: 100, MaxWarmSessions: 5000, Queue: service.QueuePolicyWait}, Admitter: service.Limits{MaxActiveRuns: 8}}`. `Bounds` guards the Instance itself and runs first, with the drain; the `Admitter` is the service's own policy and runs after them. `Admitter` is `Admit(ctx, service.Admission, service.Load) (release func(), err error)`: `service.Admission` names the Run (`SessionID`, `Agent`), `service.Load` is the Instance's counts (`ActiveRuns`, `ActiveSessions`, `WarmSessions`), and the caller's `ctx` carries who asks, so a limit per tenant is a few lines (one tenant ten Runs, another fifty). The Runner calls `release` exactly once when the Run ends, whatever its outcome, so a per-tenant count stays right. A refusal is the error `Admit` returns, marked not run (an error that is not a `*gotato.RuntimeError` is answered as `limit_exceeded`, HTTP 429). `Admit` is called with the Runner's table of Runs locked: it must be quick and must not call the Runner. The default, a nil `Admitter`, is `service.Limits{}`: no limit, and `Limits{MaxActiveRuns: n}` is today's behaviour (`ErrCapacity`, `limit_exceeded`, not run and retryable); a negative `MaxActiveRuns` is still refused by `New`. The name `service.Admission` now means the request the `Admitter` is asked about, not the settings struct. `gotato serve --max-runs` sets `Limits`.
- **Nine Instance Events moved from `gotato` to `service`** (D-048): `RunRequested`, `RunWaiting`, `RunRejected`, `SessionFenced`, `LivenessLapsed`, `SessionDeleted`, `SessionLoaded`, `SessionSaved` and `StoreWriteFailed`, with their `EventKind` constants.
  - Before: `gotato.RunRejected`, `gotato.EventKindRunRejected`; `gotato.UnmarshalEvent` decoded them to their types.
  - After: `service.RunRejected`, `service.EventKindRunRejected`, and the same for the other eight. Their kinds and JSON fields are unchanged, so no HTTP client sees a difference. A Go program that read the Instance stream switches on `service.RunRejected` and the others; `gotato.UnmarshalEvent` reads their JSON as an `UnknownEvent`, since Gotato ships no Go client that needs more. Encode one with `gotato.MarshalEvent`: `encoding/json` alone leaves the kind out. `SessionUnloaded` and `EventsSkipped`, which the core publishes itself, stay in `gotato`.
- **Five error codes moved from `gotato` to `service`, and `service.ErrorCodes()` lists them** (D-048): `CodeNotWriter`, `CodeDraining`, `CodeOverloaded`, `CodeCannotResume`, `CodeAlreadyExists`.
  - Before: `gotato.CodeNotWriter` and the rest, listed by `gotato.ErrorCodes()`; `gotato.ErrorOf(gotato.CodeDraining, ...)` came back not run and retryable.
  - After: `service.CodeNotWriter` and the rest, with the same strings (`not_writer`, `draining`, `overloaded`, `cannot_resume`, `already_exists`), so error JSON and HTTP statuses are unchanged. `gotato.ErrorCodes()` lists the core's codes, `service.ErrorCodes()` the five, and a layer that maps every code (a transport, a CLI) ranges over both. `gotato.ErrorOf` no longer knows that draining, overloaded and not_writer are not run and retryable: an error you build with one of these codes says it itself (`NotRun`, `Retryable`), or you return the service's own (`service.ErrDraining`, `service.ErrOverloaded`). `gotato.ErrEventsLost` keeps the string `cannot_resume`.
- **The host calls left the core's API for `internal/hostlink`** (D-048): `WithFeed`, `WithRunStart`, `WithQueueHandoff`, `WithRequestID`, `Session.TakeQueued`, `Requeue`, `DropQueued` and `Published`, and `NewFeed`, `NewInstanceFeed`, `Feed.MirrorTo`, `SetLabel`, `Publish`, `PublishLabeled`, `Published` and `Last`.
  - Before: a library user saw them next to `NewSession` and `Subscribe`, and could call one by mistake; each was contract ([decision 010](plan/decisions/010-gotato-is-a-light-library-with-a-versioned-contract.md)).
  - After: `gotato.Feed` has `Subscribe` and `Close`, and `Session` has the calls of a Session (`Prompt`, `Steer`, `Subscribe`, and the rest). The Runner and `testkit` use the others through function values the core sets in `internal/hostlink`, which a program outside this module cannot import; they assert their types once when they load. A program that built a `Feed` of its own or took a Session's queued messages used a call that is gone: a Session already numbers and sends its own Events, and a message queued in a bare Session is dropped when its Run ends. `Transcript.Capabilities().Events` is how a store lets a subscriber catch up from its own log. `Queued` and `EventSource` stay.

### Fixed

- `gotato` and `modelctx`: one page size. Before, a Tool Result was spilled at a fixed 32 KiB while `read_result` and `read_segment` could be built with another page, so a result could be spilled and then read at a different size. Now the `ReadBack`'s `PageBytes` is the spill threshold, the pages a preview counts and the page of both read tools (D-046).
- `modelctx`: the default Builder escapes tags in the `kind` attribute of a service's notice.
- `service`: an Agent whose `Compact.Recap` is a `*modelctx.ModelRecap` with no Model now gets the Agent's Model, like the value form. Before, only `modelctx.ModelRecap{}` was filled, so `&modelctx.ModelRecap{}` passed `Validate` and then failed with `ErrNoRecapModel`.
- `session.Writer.Write` numbers and stores its Events in one step. Before, a `Flush` from another goroutine could write them in between, and `Write` returned no Events and no error; now it always returns the Events it was given, numbered and stored.
- `adapter/mcp`: with `WithListCache`, a tool listing that fails (a canceled context, a server error) no longer loses the server's `list_changed`, so the next resolution lists again instead of serving the old list for the whole TTL. A slow listing that began before a change no longer replaces a list read after it, and a new connection to the server makes the kept list stale, since a change while no connection was open sent no `list_changed`.
- `modelctx`: a compaction in the middle of a Run keeps the Run's last reply and everything after it. Before, a notice or a steer committed after a Turn's tool results was taken as the start of the Turn, so the next model call saw none of those results; after an interrupt the cut-off reply was closed into the Segment and its text lost; and on a Run's first Turn a prompt followed by a notice could be cut into the Segment. Now the prompt is kept whole, and a prompt past the ceiling ends the Run with `limit_exceeded`.
- `modelctx`: a Turn counts as compacted only when a compaction or a merge started in it. Before, a merge at a Run's start that found nothing to merge used up the Turn's compaction, so an overflow after it ended the Run with `context_overflow` instead of compacting and sending the call again. A compaction that started and was dropped still counts.

### Changed

- **The Runner and the Session are built from parts with one job each** (D-048). The Runner holds its Liveness row (`service/internal/heartbeat`), its admitted Runs (`runs`), its warm copies (`warm`, with one eviction for both bounds) and one clock (`clock`) as parts with a lock each, in a lock order of runs, then warm. The Session holds `def`, `life`, `run`, `events`, `history`, `tools`, `queue` and `host`: four locks, ordered events, run, queue, where it had six, and a Tool Result is committed in stages by `commitResult`. Nothing here changes behaviour, an Event or an error: it is how the code is cut, so each part is read and tested alone.

- **A newly built Segment names each tool result and each kept message by a ref** (decision 043). A Segment already written is not changed and renders as before.
  - Before: a tool call line ended `→ ok` or `→ error failed`, a kept user message or final reply ended with its text, and the Segment header ended `read_segment(1) returns the segment in full.`
  - After: a tool call line ends `→ ok [result:c1]` (a repeated call lists one ref per call, `×3 [result:c2 result:c3 result:c4]`), a kept message is followed by a `<segment n="1">` part holding `ref msg:m01`, and the header adds `; read_result(ref) returns one tool result or message by its ref.` Anything that matches the old text breaks. The `read_result` tool's description and its `ref` input description changed, so the tool list of a Session differs from one built by the earlier version.
  - After: a merge's digest lines end `Refs: msg:m01 … result:c1 …` (at most 4 and 4 per Segment), and the model-written merge Recap is asked with each Recap's refs and told to keep them next to what it states.
- **The Model reads that a ToolSet is unavailable, not that its Tool is unknown.** While a ToolSet is unavailable, a call to a Tool of it fails with `tool_resolution_failure: tool "files.read" is in ToolSet "files", which is unavailable now; try again in a later Run`; `search_tools` by name lists it under `Unavailable now, its ToolSet is unavailable; try again in a later Run: …`, and `search_tools{toolset}` says `files is unavailable now; try again in a later Run.` A search by name for a Tool the Model already sees, such as a root Tool, says `Already available`. `search_tools` stays offered while any listed or folded ToolSet is installed.
  - Before: the call said `unknown tool "files.read"`, the search `Not found: files.read.`, the listing `files has 0 tools:`, a search for a root Tool `Not found`; and `search_tools` left the tool list when no catalog Tool could be loaded, such as while the only ToolSet was down.
  - After: the texts above, and the tool list keeps `search_tools`.
- **A Tool call ends at its `ToolCallDeadline`, even when the Tool ignores its `ctx`.** The call fails with the text `deadline_exceeded: the tool did not finish within ToolCallDeadline (<d>); its outcome is unknown`, recorded as executed, and the Run goes on. The Tool's goroutine runs on until `Execute` returns, and its late result is dropped.
  - Before: the deadline only canceled the Tool's `ctx`. A Tool that ignored it held the Run until it returned, and its late result was kept; a Tool that honored it failed with `tool_execution_failure: tool failed`, which did not say it timed out.
  - After: the Run stops waiting at the deadline, and in both cases the Model reads that the call timed out.
- **A panic in host code fails its owner, never the process or a lock; a subscription filter runs outside the Feed's lock.** `Transcript.Len` and `Messages`, `LoadedTools`, `SpillKeeper`, `Durable`, `WithRunStart`, `PublicError.Public`, `AdvisoryExtension.Advisory`, a filter, `SubscribeUntil`, `SubscribeVerify` and `EventSource.EventsAfter` are guarded like the Model and the Tools.
  - Before: a panic in any of them ended the process; a `SubscribeFilter` that panicked left the Feed's lock held and the Session hung; a filter that called its Subscription's `Close` (or `End`, while the Subscription read its source) blocked every publisher of the Feed, and of the Instance's Feed.
  - After: a `Transcript`, `LoadedTools` or `WithRunStart` panic fails the Run (`internal_invariant` or `extension_failure`); an `Advisory` that panics is blocking; a panic in a filter, `SubscribeUntil`, `SubscribeVerify` or `EventsAfter` ends that Subscription, and its `Next` returns a `*RuntimeError` with `extension_failure`. A filter may call `Close` or `End`. A Journal and a `Store` are still called under the write-ordering lock and must not call back into the Session.
- **A Tool's `Spec` is read once, when the Tool is resolved.** The Session keeps it: a root Tool's from `NewSession`, a `ToolSource`'s Tools' from each Turn, a `ToolSet`'s Tools' from each resolution. A Tool whose `Spec` panics, or a typed nil, now fails its whole source like any other bad Tool, instead of the process.
  - Before: `Spec` was read again on every rebuild of the Tool list, so a Spec that changed showed at once, and a Spec that panicked ended the process.
  - After: a Spec that changes shows at the next resolution of its source. Return a stable value, and supply Tools that change through a `ToolSource` or a `ToolSet`.
- **Core owns a `ToolResult`'s `CallID`, `Executed`, `Spilled` and `LoadedTools`, wherever the result comes from.** A Tool's own result, a `PostToolUse`'s and a `PreToolDecision.Result` keep Core's values for all four.
  - Before: a Tool or a `PostToolUse` could set `LoadedTools` and `Spilled`, which reached the Record and a gateway's native tool references; a `PostToolUse` that rebuilt a `search_tools` result dropped its `LoadedTools`.
  - After: only `search_tools` and the refusal of a call to a Tool that was not loaded list loaded Tools; `Spilled` is set only by Core's spill; a `PostToolUse` that rebuilds a result keeps all four.
- **`ToolSource`s are asked at once, with no lock held, and `WithToolFilter` is asked when the Tools are resolved.** A slow `ToolSource` no longer holds `Session.Tools` or `Session.ToolSets`.
  - Before: the ToolSources were asked one after another under the registry's locks; the filter ran on every rebuild of the Tool list, under the locks, and a filter that panicked ended the process.
  - After: the filter is asked at `NewSession`, at the start of every Run and at every Turn of a Session with a `ToolSource`; a change to its answer shows at the next of them. A filter that panics fails the Run (or `NewSession`) with `extension_failure`.
- **A Tool loads when the Tool Result that loads it commits, and only then.** The load and its `tool_loaded` are one write with that result, so what the Model was told and what the Session offers agree.
  - Before: loads waited for the end of the batch. A load the Model had been told of was lost when a later call of the same batch failed the Run (on a Transcript that is not a Record); a `search_tools` call that failed still loaded the Tools it named; a `search_tools` call that outlived its canceled Run could load a Tool into the next Run.
  - After: `Session.Tools` shows a load as soon as its result commits, inside the batch. A failed `search_tools` call loads nothing, and a call that returns after its Run ended loads nothing.

### Fixed

- **A Run that fails while it commits queued messages no longer loses them.** Steer, FollowUp, Interrupt and notices share one internal queue, and what a Run takes from it and does not commit goes back.
  - Before: a commit that failed (for example at `MaxMessages`) lost every other message the Run had taken: their `message_queued` was never closed, and `TakeQueued` did not return them.
  - After: they stay queued, so the Run's end drops them (`run_ended`) or, with `WithQueueHandoff`, the host takes them. The Runner hands them to the following Run, and closes the `message_queued` of its first message with `run_failed` when that Run ends before committing it.
- **A Steer is never queued and then rejected.** The place in the queue is reserved before `message_queued` is written.
  - Before: concurrent Steers at the limit could each write `message_queued` and then be refused with `message_rejected` (`queue_full`).
  - After: a full queue refuses before anything is queued.

### Added

- `modelctx.Compactor` and its parts (D-046): `SegmentStore`, `Trigger` (`CeilingTrigger`, `TurnState`), `Cutter` (`TailBudget`, `CutInfo`), `Builder` (`CodeSegments`, `SegmentInfo`), `MergeRecapWriter` and `RecapWriter` (no default), and `Picker` (`OldestToHalf`). The frame alone writes and keeps the guarantees whatever a part returns; a part that fails, panics or breaks a rule drops that compaction, never the Run. New `modelctx.ErrBadPart` (code `extension_failure`) and `modelctx.MergeReasonPickFailed`; a Trigger that fails publishes `extension_failed` with stage `compaction_trigger`.
- `gotato.ReadBack` and `gotato.WithReadBack`; `CoreLimits.SpillPreviewBytes`; the public package `ref`; `modelctx.ReadBack`, `modelctx.Originals`, `modelctx.RecordOriginals` and `modelctx.DefaultPageBytes` (D-046).
- `gateway`: four layers a team can replace, each with a default (D-045): `WireAPI` (`ChatCompletions`, `Responses`, `AnthropicMessages`, or your own), `Connection` with `NewHTTPClient`, `Retry` with `DefaultRetry` and `WithRetry`, and `Classifier` with `Failure`, `Verdict`, `DefaultClassifier` and `WithClassifier`. `gotato.ModelConfig`, `ModelFacts`, `Sampling` and `Window` describe the model once; `Model.Config()` returns it, and `gateway.New(wire, connection, model, opts...)` takes it.

They are additive: no field changed, and an old Record without them reads them as 0.
- **`read_result` also reads a Tool Result that was never spilled, and a Message, by their refs** (decision 043): `result:<call_id>` for any Tool Result of a Segment's calls, `msg:<message_id>` for a user message or a final reply a Segment kept. Same pages, same Effect (`read`). It is offered whenever `read_segment` is, also to an Agent with no tool. Reasoning has no ref and is not read back; a ref into pruned Entries reads as removed.
- **`message_dropped` has the why `commit_failed`.** It closes the one message a Run took and could not commit (it would fail again in the next Run); the messages behind it go back to the queue.
- `adapter/mcp`: `WithDefaultEffect(effect)` sets the Effect of a tool whose server sent no annotations; without it such a tool is `destructive` and `WithMaxEffect` hides it (D-004).
- `adapter/mcp`: `WithToolFilter(keep)` leaves a tool out, listed in `Skipped()` as `filtered`, and `WithToolRename(rename)` changes the name the Model sees while the Effect option, the filter and the call to the server keep the server's name (D-002).
- `adapter/mcp`: `WithSequentialWrites()` marks every tool above `read` as `Sequential`; the default is unchanged, so with `MaxParallelTools` above 1 a server's write tools still run in parallel without it (D-021).
- `Code` on `ToolResult` and `ToolEnded`, and `CodeToolNotLoaded`; the reworded `search_tools` line tells the Model to load first (D-026, D-018). Whether the refused calls drop is measured before D-018 goes further.
- `ToolUse.SessionID` names the Session of a call, for a `PreToolUse` that asks a person (D-022).
- `inspect` shows the compaction ceiling always, 0 when off (D-020, the inspect part; the warning is not part of this line).
- `gateway`: the chat wire reads `cache_read_input_tokens` and `cache_creation_input_tokens` (D-019).
- `examples/larkbot`: a streaming card, and the Lark `message_id` as the `RequestID` (D-006, D-007).

## 0.2.0 — 2026-10-29

Gotato 0.2.0 is the first release: a minimal, synchronous, Go-native agent runtime that runs on its own in a small `main` and embeds into running, multi-instance Go services. It needs Go 1.24 (the MCP adapter needs Go 1.25).

The first release is 0.2.0 because versions 0.1.0 and 0.1.1 of the module path were published by mistake before it, hold other code, and are retracted.

**In this release**

- **What ships:** the core and the packages around it, and one adapter module.
- **What it promises:** from this release on, a break is written down.
- **What was never checked:** everything that only a real provider or a real model can show.

### What ships

| Package | What it is |
|---|---|
| `gotato` | The core: Agent, Session, Tool, Model, Event. Standard library only; it runs by itself, with the conversation in memory. |
| `session`, `session/storetest` | The Record and its Store (memory and file), and the suite that proves a Store adapter keeps the store contract. |
| `modelctx` | The ContextBuilder and compaction: the model receives a built, bounded view, not the full history. |
| `gateway` | A provider is YAML, not code: the OpenAI Chat Completions, OpenAI Responses and Anthropic Messages wire APIs. |
| `service`, `service/httpapi` | The Runner that runs Sessions on many instances over one Store, and its HTTP and streaming surface under `/v1/sessions`. |
| `testkit` | Fake and replay models and tools, and Event recorders, for deterministic tests. |
| `adapter/mcp` | A module of its own: an MCP server's tools as a `ToolSet`. Tagged `adapter/mcp/v0.2.0`. |

The test CLI (`internal/cmd/gotato`), the workload tools, `examples/larkbot` and `bench/refservice` are in the repository but are not part of the release's promise. The CLI is our test tool and keeps no contract.

### What it promises from now on

- A breaking change to the Go API, the HTTP contract or the Event kinds has a CHANGELOG entry with a before and after.
- Where the cost is low, the old symbol stays for at least one release with a `// Deprecated:` comment.

### What was never checked against a real provider

Gotato runs no tests against real providers, and CI has no provider credentials. A provider's behavior is played by a fake gateway (`internal/fakegateway`) built from the providers' public wire formats. One live run exists (2026-10-16, one model, before later changes, G-F22); it was not repeated for this release. The list below is for a team to check on its own gateway.

- **The wire APIs ([G-F07](FEATURES.md#g-f07--models-and-providers-)).** `openai-chat-completions`, `openai-responses` and `anthropic-messages` are tested on request bytes and against the fake gateway, which refuses a request shaped otherwise than the documentation. Its quirks (a refusal as too long, a cut stream, cached tokens, a reasoning replay, a mid-conversation message, a slow reply) follow the documented shapes, not a provider's live answers.
- **The wording of a refusal as too long ([G-F07](FEATURES.md#g-f07--models-and-providers-), TODO "Do the providers word a refusal as too long as the fake gateway does?").** The wordings are the ones the providers are reported to return, and the public documentation quotes none.
